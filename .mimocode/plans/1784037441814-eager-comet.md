# 全局搜索增强方案

## 需求总结

1. 搜索框默认显示 "搜索（F）"
2. 加载索引时：搜索框右上角动态显示 0% → 100% 进度
3. 加载完毕后：显示 "搜索 100%（F）"
4. 快捷键 F：全局搜索获取焦点
5. 搜索结果支持方向键上下选中 + 回车跳转

## 涉及文件

| 文件 | 操作 |
|------|------|
| `docs/js/search-index.min.js` | **重写** — 添加进度显示、快捷键、键盘导航 |
| `docs/index.html` | 无需修改 |

## 当前搜索架构

- 索引文件：`search-index.json`（640KB，671 条记录）
- 加载方式：XHR 一次性加载
- 插件：`search-index.min.js`（213 行），纯 vanilla JS，不依赖 jQuery/Docsify API

## 实现方案

### 1. 搜索框 UI 改造

将搜索框从纯 `<input>` 改为带进度指示器的结构：

```
┌─────────────────────────────┐
│ 搜索（F）            0%    │  ← 加载中
├─────────────────────────────┤
│ 搜索（F）           100%   │  ← 加载完毕
├─────────────────────────────┤
│ 🔍 搜索内容...      100%  × │  ← 输入内容后
└─────────────────────────────┘
```

**HTML 结构变化**：
```html
<div class="search">
  <div class="input-wrap">
    <input type="search" placeholder="搜索（F）" />
    <span class="search-progress">0%</span>   <!-- 新增：进度指示器 -->
    <div class="clear-button">×</div>
  </div>
  <div class="results-panel"></div>
</div>
```

### 2. 索引进度动态显示

由于 `search-index.json` 是一次性 XHR 加载（无法获取真实下载进度），采用**分阶段模拟进度**：

| 阶段 | 进度 | 说明 |
|------|------|------|
| 开始加载 | 0% | 触发 XHR 请求时 |
| 下载中（心跳） | 1%→15% | 每 200ms +1%，给用户"正在加载"的反馈 |
| JSON 解析完成 | 100% | 立即跳到 100%，颜色变绿 |

- 进度 < 100% 时：灰色文字
- 进度 = 100% 时：绿色（`var(--theme-color, #42b983)`）
- 100% 后**永久保留显示**，搜索框始终显示 "搜索 100%（F）"

### 3. 快捷键 F

```javascript
document.addEventListener('keydown', function(e) {
    // 排除：输入框内、textarea、select、已按下 ctrl/alt/meta
    if (e.key === 'f' && !isInputFocused() && !e.ctrlKey && !e.altKey && !e.metaKey) {
        e.preventDefault();
        searchInput.focus();
        searchInput.select(); // 选中已有文本
    }
});
```

**注意事项**：
- 浏览器默认 Ctrl+F 是页面内搜索，这里用的是单独的 F 键
- **搜索框获焦时禁用 F 键快捷键**：避免用户想输入字母 f 时触发聚焦
- Esc 键让搜索框失焦

### 4. 搜索结果键盘导航

维护一个 `selectedIndex` 状态：

| 按键 | 行为 |
|------|------|
| ↓ | `selectedIndex++`，滚动到可视区域 |
| ↑ | `selectedIndex--`，滚动到可视区域 |
| Enter | 跳转到 `results[selectedIndex].url` |
| Esc | 清空搜索框，关闭结果面板 |

**视觉反馈**：
- 选中项添加 `.active` 类：背景色高亮（`var(--theme-color, #42b983)` 10% opacity）
- 选中项自动滚动到可视区域（`scrollIntoView({ block: 'nearest' })`）

## 方案不足与建议

### 不足

1. **进度不精确**：XHR 不支持 `onprogress` 事件（本地/同源文件），心跳模拟的进度与实际下载无关
2. **快捷键冲突**：单独的 F 键可能与其他插件或浏览器扩展冲突（如 Vimium 等）
3. **移动端无快捷键**：F 键仅桌面端有意义，移动端需保持搜索框易触达
4. **大索引性能**：640KB 索引一次性解析，搜索时遍历 671 条记录，极端情况下可能有短暂卡顿

### 改进建议

1. **进度优化**：如果后续索引拆分为多片（参考 `search.js` 的 IndexedDB 分片方案），可以实现真正的逐片加载进度
2. **快捷键可配置**：在 `window.$docsify` 配置中增加 `searchHotKey` 选项，默认 'f'
3. **搜索结果懒渲染**：超过 20 条时只渲染可视区域，滚动时动态加载（当前上限 50 条，影响不大）
4. **考虑用 `fetch` + `ReadableStream`**：可以获取真实下载进度，但需要现代浏览器支持

## 验证方式

1. 本地启动 `docsify serve docs`
2. 验证搜索框默认显示 "搜索（F）"
3. 清除缓存后刷新，观察进度从 0% 动态变化到 100%
4. 按 F 键，验证搜索框获得焦点
5. 输入搜索词，用方向键上下移动，验证高亮和滚动
6. 按回车，验证跳转到正确页面
7. 按 Esc，验证搜索框失焦/清空
